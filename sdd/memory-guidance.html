User outcome

Who: someone who pastes the suggested block into AGENTS.md / CLAUDE.md (directly, or via agentic-loadout). Outcome: their agents write fewer stale or noisy memories and fix wrong ones when they notice them, while recall quality does not drop.

Example. Today the block says how to call the tools but never says what is worth saving. This repo's own memory/activeContext.md shows the result: commit hashes, a CI run URL and “89 unit tests pass” copied into the “next steps”, all re-derivable from git and already outdated.

Boundary. Prose guidance, one optional template line, one changelog entry. The product is a Markdown document, so the “user interface” is the text an agent reads.

decisions.md says “default decider: Jev”; a later session note says “QSIV”. Proposed: keep both as CONFLICT: Jev, 2026-10-26, decisions.md says...; QSIV, 2026-11-02, session note says...; ask the user rather than choose.

F4 · a passing remark vs a recorded decision

A session says “we probably don't use X anymore” after a search found nothing. Proposed: this is not a correction of the recorded decision; leave the decision, optionally add a CONFLICT entry citing the remark as a weak claim.

Parallel agents in one checkout each rewrite progress.md; the later save erases the earlier. Proposed: each writes memory/<topic>.md and links it; notes written via MCP are already transaction-safe. Different worktrees do not collide (separate files, git merge).
