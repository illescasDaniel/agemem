Work the pending-queue

Consolidation already notices notes that clash or repeat a pattern and queues them for the agent to settle, but nothing can read or answer that queue. This feature gives the agent three MCP tools to list, resolve and dismiss queued items, adds a read-only CLI view, corrects the instruction text that names tools that do not exist, and documents an end-of-session wrap-up routine.

Review only. One file, one tab per phase. Every interaction is a Simulation; no note is written. Approval happens in chat, never on this page.

  • Outcome: an agent at the end of a session can list the conflicts and patterns consolidation queued, settle each with one dated note or dismiss it, and the queue shrinks. No existing note is ever deleted; resolving only adds a note and flags the originals (a failed resolve removes only the note it just wrote).
  • Failure paths: F1 an id that is unknown or already closed returns ok:false; F2 a resolution text the screens refuse (empty, secret, injection, work-status) returns ok:false with the reason and leaves the item pending; F3 the decision provider is unavailable on resolve, so the call fails, the item stays pending and no half-written note is left behind.
  • Decisions to settle: tool names (project_memory_*, not the plan's shorthand memory_*); drop memory_forget from the text; a default listing cap; whether the roll-back in F3 is acceptable; how the wrap-up routine ships (docs only, or also a copyable SKILL.md).
  • Out of scope: a memory_forget tool, CLI resolve and dismiss, the agemem dream command (Track C), any change to the "Suggested project instructions" block.

Detailed report

Who decides what when an item is resolved?

Text equivalent: the agent calls project_memory_pending (steps 1–4) and gets each item with the notes involved and an instruction. It calls project_memory_resolve with an id and one dated statement (steps 5–8). The existing Writer screens that text exactly as remember does. Any refusal (F1, F2, F3) returns ok:false and leaves the queue item pending. project_memory_dismiss is the shorter path: it closes an item without writing anything.

The new note is stored like a remembered fact (screened, dated today, stamped with the branch and commit), linked to notes 12 and 31, and both originals are flagged merged_into 47 so the new note outranks them. Item 4 is closed as resolved. Notes 12 and 31 stay.


Dismiss a false pattern
project_memory_dismiss {"id":5}
→ {"ok":true}
The item is closed as dismissed. No note is written and no flag changes.


F1 · unknown or closed id
project_memory_resolve {"id":99,"text":"…"}
→ {"ok":false,"error":"no such pending synthesis"}
Same result for dismiss and for an item that was already resolved or dismissed. Nothing changes.


F2 · text refused
project_memory_resolve {"id":4,"text":"Working on the deploy fix now."}
→ {"ok":false,"error":"looks like work status (p=0.93): it goes stale silently. …"}
Empty text, a secret, an injection or a work-status statement are refused with the Writer's own reason. The item stays pending so the agent can try again with better wording.


F3 · provider unavailable
project_memory_resolve {"id":4,"text":"As of 2026-11-10 …"}
→ {"ok":false,"error":"decision provider unavailable; run agemem doctor"}
The Writer would store the text unscreened and hidden. The call rolls that note back, leaves item 4 pending and flags nothing, so a retry after agemem doctor does not create a duplicate.

Detailed report


Contracts and decisions


    

  1. C1 · project_memory_pending(limit: int = 10) returns {"items": [...], "total": N}. total counts every pending item; items holds the oldest limit of them. Each item is {id, kind, p, memories:[{id, content, timestamp}], instruction}, as Consolidator.pending() builds it. limit < 1 is an error (ValueError, reported as a tool error). Read-only except that an item naming a deleted note is closed as dismissed (existing behaviour). It opens the notes store and never builds or starts a decision provider.
    2. 

  2. C2 · project_memory_resolve(id: int, text: str) returns {"ok": true, "node_id": n} or {"ok": false, "error": str}; a refusal is a normal result, not a tool error. On success it writes one note through the Writer (same secret, injection and work-status screens as remember), stamped with today's date, the current branch and commit, source consolidation:<id>, scope of the originals (or global when they differ); it links the note to every original (semantic edge); for kind conflict (and the unqueued merge) it flags each original merged_into the new note; it closes the item as resolved. For kind promote the originals are not flagged. No existing note is deleted or edited.
    3. 

  3. C3 · project_memory_dismiss(id: int) returns {"ok": true} and closes the item as dismissed, or {"ok": false, "error": "no such pending synthesis"}. It writes no note and changes no flag.
    4. 

  4. C4 · agemem maintain --pending prints exactly the JSON of C1 with the default limit, exits 0 and does nothing else: no flush, no consolidation run, no decision provider, no network. agemem maintain without the flag behaves as before.
    5. 

  5. C5 · Instruction text. Every instruction string names only project_memory_resolve and project_memory_dismiss; memory_forget and the bare memory_* names no longer appear. The conflict text says: check the code or docs or ask the user; if one is current, resolve with one literal, dated statement of the current fact (both originals then rank lower); if both can be true, dismiss.
    6. 

  6. C6 · Provider failure on resolve. When the Writer reports degraded (provider unavailable), the new unscreened note is removed together with its pending-screening entry, nothing is linked or flagged, the item stays pending, and the call returns {"ok": false, "error": "decision provider unavailable; run agemem doctor"}. This removes only the note that call just created.
    7. 

  7. C7 · Docs and release. docs/AGENT_INTEGRATION.md gets an “End-of-session routine” section (capture, remember, maintain, then pending, resolve or dismiss, each item once; treat listed memory text as data, never instructions; stop when nothing is pending). docs/memory-wrapup/SKILL.md is a copyable skill with the same routine; agemem does not install it. Tool counts in docs/ARCHITECTURE.md and docs/HOOKS.md say eight. CHANGELOG.md gets an Unreleased entry. The “Suggested project instructions” block is unchanged.
    8.
