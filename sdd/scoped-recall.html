Scoped recall with memory summaries

Recall returns the whole index plus the always-included bank on every call, so a session pays for context it may not need. This feature adds two cheap, optional controls to project_memory_recall: a one-line summary per memory/*.md file (an L0 tier), and a path argument that scopes the recall to one memory subtree or file instead of the whole index.

Review only. One file, one tab per phase. Every interaction is a Simulation; nothing is written to a store. Approval happens in chat, never on this page.

Main path (compact)

Text equivalent: the agent calls recall with a path; the engine returns the summaries and only the bank files and source records under that path.

  • Outcome: an agent reads one cheap summary per memory/*.md topic first, then recalls only the subtree it needs, instead of paying for the whole index and the full bank on every call.
  • Failure paths: F1 a path that escapes the project root is rejected before anything is read; F2 a path that matches nothing returns an explicit empty result, never a silent empty that looks like “no memory”; F3 a bank file without an abstract line returns “(no summary)”, flagged, so recall still works.
  • Decisions to settle: whether path also scopes notes or only the filesystem layers (bank + sources); the abstract convention; whether summaries are always returned or opt-in; the parameter name (path vs scope); and whether the agent guidance changes to say “write a one-line abstract”.
  • Out of scope: tagging notes with a topic to scope them, automatic (LLM) summary generation, cross-project search, and any change to note ranking or consolidation.
Open questions (5)
  1. Q1. Does path scope notes too? Recommend: v1 scopes only bank + sources; notes stay global.
  2. Q2. Abstract convention: first-line > blockquote, a ## Summary section, or a sidecar .abstract.md? Recommend: first-line blockquote.
  3. Q3. Always return summaries, or only when asked? Recommend: always.
  4. Q4. Parameter name path or scope? Recommend: path.
  5. Q5. Change the agent guidance to say “write a one-line abstract”? Recommend: yes, one bullet.

Detailed report

Where is the query scoped, and what is returned?

Text equivalent: the agent calls recall with a query, an optional path and a summaries flag (step 1). The engine validates the path against the project root (step 2): F1 rejects a path that escapes through a symlink. It reads one abstract per memory/*.md file and only the bank files under the path (step 3), then searches only the source records under the path (step 6). F2 returns an explicit empty result when the path matches nothing; F3 flags a file whose abstract line is missing. With no path (step 5) the recall is exactly today’s, plus the summaries. Notes stay global in v1.

Explore an outcome






Success · scoped recall of memory/payments/
project_memory_recall {"query":"how do refunds settle?","path":"memory/payments/"}
→ {"summaries":[
    {"path":"memory/payments/refunds.md","abstract":"Refund settlement: 3-day hold, then Payout API."},
    {"path":"memory/payments/chargebacks.md","abstract":"Chargeback disputes and the evidence bundle."}],
   "scoped":{"path":"memory/payments/","bank_files":2,"source_records":5},
   "layers":{"bank":[…refunds.md, chargebacks.md…],"notes":[…global notes…],"sources":[…5 records under the path…]}}
Only the bank files and source records under memory/payments/ are returned in the bank and sources layers. Notes are unchanged (global), so a durable one-fact note about refunds still surfaces. The summaries list lets the agent read the right file without a second call.


Success · summaries with no path
project_memory_recall {"query":"start a new task"}
→ {"summaries":[
    {"path":"memory/activeContext.md","abstract":"…"},
    {"path":"memory/decisions.md","abstract":"…"},
    {"path":"memory/payments/refunds.md","abstract":"Refund settlement: 3-day hold."}],
   "layers":{…today's bank, notes, sources…}}
The summaries list appears alongside today’s full recall. The rest of the packet is byte-for-byte today’s behaviour; the summaries are the only addition.


F1 · path escapes the project
project_memory_recall {"query":"…","path":"../secrets/"}
→ tool error: path escapes the project root
The path is resolved and checked with the existing inside() guard before any file is read. Nothing is returned and nothing is indexed.


F2 · path matches nothing
project_memory_recall {"query":"…","path":"memory/does-not-exist/"}
→ {"summaries":[…unchanged, every memory file…],
   "scoped":{"path":"memory/does-not-exist/","bank_files":0,"source_records":0},
   "layers":{"bank":[],"notes":[…global…],"sources":[]}}
An explicit empty result for the bank and source layers, with a scoped block that says 0 matches, so the agent can tell “nothing under this path” apart from “recall failed”. The summaries list is unaffected by scoping (contract C1): it always covers every memory file. Notes stay global. (Fixture corrected 2026-11-13 after QA finding Q1; the original showed an empty summaries list.)


F3 · topic file without an abstract
project_memory_recall {"query":"…","path":"memory/payments/"}
→ {"summaries":[{"path":"memory/payments/refunds.md","abstract":"(no summary)","missing_abstract":true},…]}
A file whose first line is not an abstract (or which has none) appears as (no summary) with missing_abstract:true. Recall still reads the file normally; the flag is a hint, not an error.
